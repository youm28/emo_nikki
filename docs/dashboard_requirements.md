# emo_nikki ダッシュボード機能 要件定義書

- 版: 1.0（2026-07-23）
- 対象リポジトリ: `emo_nikki`（Flutter Web 感情記録アプリ）
- 目的: この文書だけを読めばダッシュボード機能を実装できる状態にする

---

## 1. 背景と目的

### 1.1 プロジェクトの背景

emo_nikki は、元研究システム（Apple Watch アプリ「Emoji_watch」＋ Streamlit ダッシュボード「emosy」＋ロボット「BOCCO emo」連携）を Flutter Web で再構成するプロジェクトである。

元研究では「記録（Watch）」と「閲覧（別アプリの Streamlit ＋トークン付き URL）」が分離していた。本プロジェクトの研究上の差分は、**記録と閲覧を 1 つのアプリに統合し、記録直後に本人が自分の感情推移を確認できる**ことである。

### 1.2 本機能の目的

1 日の感情記録の推移を「絵文字がそのままデータ点になる折れ線チャート」で可視化するダッシュボード画面を、既存の記録アプリに追加する。

### 1.3 現状のアプリ（実装済み）

- `lib/main.dart` 1 ファイル構成
- ユーザー名登録（`shared_preferences`、キー `username`）→ 12 種絵文字グリッド → 確認ダイアログ → 位置情報取得（geolocator、失敗時 null 続行）→ Firestore 保存 → 送信中インジケータ＋成功/失敗 SnackBar、まで動作する
- 絵文字 PNG は `assets/emoji_list/{name}.png` に配置済み。画像が無い場合は Unicode 絵文字でフォールバックする共通ウィジェット `EmojiImage` がある

## 2. データ仕様（既存・変更禁止）

### 2.1 Firestore 構造

```
users/{username}/emotions/{自動ID}
  day:       string  "yyyy/MM/dd"（例 "2026/07/23"）
  time:      string  "HH:mm"（例 "18:40"）
  emoji:     string  Unicode絵文字（例 "😁"）
  name:      string  画像ファイル名・拡張子なし（例 "BeamingFaceWithSmilingEyes"）
  valence:   number  感情価（2.88〜7.83 の固定値のいずれか）
  arousal:   number  覚醒度
  activity:  string | null  行動の画像ファイル名（例 "work"）。未入力なら null
  lat:       number | null
  lng:       number | null
  createdAt: timestamp（serverTimestamp）
```

- `activity` は後から追加したフィールド。これより前の記録には存在しないので、
  読み取り側は「無い／文字列でない場合は null」として扱うこと
- ダッシュボード自体は読み取り専用（上記以外のスキーマ変更は行わない）
- 1 日分の取得は `where('day', isEqualTo: 'yyyy/MM/dd')` の文字列一致クエリで行う（追加インデックス不要）
- ソートは `time` 文字列の昇順でクライアント側で行えば十分

### 2.2 絵文字マスタ（`kEmojiList`、main.dart に定義済み）

12 種固定。`name` と `valence`/`arousal` の対応はこのリストが正である。

## 3. 機能要件

### F1. 画面遷移

- 絵文字グリッド画面（`EmojiGridPage`）の AppBar にグラフアイコン（`Icons.bar_chart` 等）を追加し、タップでダッシュボード画面へ遷移する
- ダッシュボードからは戻るボタンでグリッドに戻る
- ユーザー名は既存の仕組み（shared_preferences）から引き継ぐ

### F2. 感情推移チャート（最重要・本機能の中核）

「絵文字＝データ点」の折れ線チャート。チャートライブラリは使わず Flutter 標準で自前描画する（理由は §5）。

| 項目 | 仕様 |
|---|---|
| データ点 | 記録した絵文字そのものを `assets/emoji_list/{name}.png` で表示（36〜40px）。画像が無い場合は Unicode 絵文字にフォールバック（既存 `EmojiImage` を流用） |
| 折れ線 | 単色コーラル系（例 `#F0997B`）、太さ 2〜3px、時刻順に直線接続。絵文字の背面に描く |
| 縦軸 | Valence。**1〜9 の固定スケール**（日によってスケールを変えない。日間比較のため）。目盛りは 3 本程度（例 2, 5, 8）で極薄に |
| 横軸 | **時刻に比例配置**。軸範囲は **10:00〜20:00 で固定**、縮尺も **1分 = 1px で固定**する。日や画面幅によって範囲・縮尺が変わると同じ時刻が別の位置に来てしまい、日をまたいだ比較ができないため。画面に入らない分は**横スクロール**する（縦軸ラベルはスクロール領域の外に置いて常に見えるようにする）。目盛りは1時間おき |
| 範囲外の記録 | 10:00〜20:00 の外の記録はチャートには描かない。ただし記録数・平均・推定感情・履歴には含める。チャート下に「範囲外の記録が N 件あります」と表示して、隠していないことを分かるようにする |
| 初期スクロール位置 | その日の最初の記録（範囲内）の少し手前。範囲内に記録が無い日は左端（10:00）。日付を切り替えたときも同様に合わせ直す |
| 軸・グリッド | 絵文字が主役。軸線・グリッド線・ラベルはすべて控えめ（細く薄く） |
| 重なり処理 | 縮尺固定により **30分以上離れた記録は必ず真の時刻位置に出る**。30分より近くて重なる場合だけ、本来の時刻を中心に左右対称へ広げて最小間隔（マーカー幅）を確保する |
| タップ | （任意）マーカータップで時刻・Valence 値をツールチップ表示 |

### F3. サマリーカード

チャート上部に 3 枚のカードを表示する。

1. **今日の記録数**（n 件）
2. **推定感情（ピーク値法）**: Positive / Neutral / Negative を日本語（ポジティブ等）＋ピーク記録の絵文字で表示
3. **平均 Valence**（小数 1 桁）

#### ピーク値法の仕様（元研究 `peak_value_estimator.py` の移植）

```
VALENCE_MIN = 2.88, VALENCE_MAX = 7.83
normalize(v) = 2 * (v - VALENCE_MIN) / (VALENCE_MAX - VALENCE_MIN) - 1   // [-1, 1]
その日の全記録のうち |normalize(v)| が最大の記録を「ピーク」とする
ピークの正規化値 p について:
  -0.176 <= p <= 0.140 → Neutral
  p > 0.140            → Positive
  p < -0.176           → Negative
記録が 0 件の日は Neutral（ただし F5 の空状態を優先表示）
```

チャート上のピーク記録のマーカーは視覚的に強調する（例: 薄いリング、または「ピーク」ラベル）。

### F4. 日付ナビゲーション

- デフォルトは今日。◀ ▶ ボタンで前日・翌日に移動
- 現在表示中の日付を「2026/07/23（木）」形式で表示（`intl` パッケージ使用可）
- 未来日への移動は今日まででガードする

### F5. 空状態

記録が 0 件の日は、チャートの代わりに「この日の記録はありません」を中央に表示する。サマリーカードは「0 件 / − / −」とする。

### F6. 入力履歴リスト

チャート下に、その日の記録を時刻降順で一覧表示する（時刻・絵文字・valence 値）。行数が多い場合もスクロールはページ全体に任せる（リスト内スクロールは作らない）。行動が入力されている記録は、アイコンとラベル（例「仕事」）も併記する。

### F7. 行動レーン

チャートの時刻ラベルの下に、感情マーカーと**同じ x 座標**で行動アイコンを並べる。縦に並ぶことで「そのときの気分」と「していたこと」の対応が読み取れる。

- 行動が未入力の記録はレーンに何も置かない（間が空く）
- その日に行動が 1 件も無ければレーン自体を表示せず、チャートの高さも詰める
- 行動マスタは 17 種固定（`lib/activity.dart` の `kActivityList`）。アイコンは
  `assets/activity_list/{name}.png`、表示名は同ファイルの `labelJa`

行動の入力は記録画面側の確認ダイアログで行う（任意入力。未選択でも記録できる）。

## 4. 非機能要件

- **プラットフォーム**: Flutter Web（既存アプリに統合。別アプリ・別デプロイにしない）
- **追加パッケージ**: 原則不要。日付整形に `intl` の追加のみ許可。チャートライブラリ（fl_chart 等）は使わない
- **レイアウト**: 記録画面と同様に最大幅を制限（チャート部は最大 680px 程度）し、スマホ幅でも崩れないこと
- **エラー処理**: Firestore 読み取り失敗時は SnackBar またはインライン表示でエラーを伝え、リトライ手段（再読み込みボタン等）を用意
- **リアルタイム更新は不要**（画面表示時に 1 回取得。記録画面から戻ってきた際は再取得する）

---

## 5. 実装方針（推奨）

- チャートは `LayoutBuilder` ＋ `Stack` ＋ `CustomPaint` で自前描画する
  - `CustomPaint`: 折れ線（ポリライン 1 本）と目盛り線
  - `Positioned` ＋ `EmojiImage`: 絵文字マーカー
  - 座標変換: `time → x`（軸範囲を幅に線形写像）、`valence → y`（1〜9 を高さに線形写像）の 2 関数
  - チャートライブラリを使わない理由: マーカーを任意画像にする自由度が高く、この図は「線 1 本＋画像 n 枚」で構成が単純なため
- ピーク値法・記録のパースはウィジェットから分離した純粋関数にする（テスト可能にするため。`buildEmotionRecord` と同様の流儀）
- ファイル構成は任意だが、`lib/main.dart` が肥大化するなら `lib/dashboard_page.dart` 等への分割を推奨

## 6. スコープ外（今回は実装しない）

- 3 日表示・週表示・月表示
- 地図表示（lat/lng の利用）
- クラスタ円グラフ・累積グラフ
- リアルタイム自動更新（snapshots）
- 通知・リマインダー
- 他ユーザーの閲覧、認証強化
- BOCCO・LLM 連携（サーバー側の別プロジェクトで行う）

## 7. 受け入れ基準

1. グリッド画面から 1 タップでダッシュボードに遷移でき、戻れる
2. 今日の記録が、時刻比例の横軸上に絵文字マーカー＋コーラルの折れ線で表示される
3. 縦軸は常に Valence 1〜9 固定である
4. サマリーカードの推定感情が §F3 のピーク値法の定義と一致する（例: 2.88 と 7.83 が両方ある日は、|normalize| が等しいため先に現れる方がピーク。7.83 のみが最大なら Positive）
5. 記録 0 件の日に空状態が表示され、エラーにならない
6. ◀ ▶ で日付を移動でき、未来日には進めない
7. 絵文字 PNG が無い環境でも Unicode 絵文字で表示が崩れない
8. `flutter analyze` が警告なしで通る
